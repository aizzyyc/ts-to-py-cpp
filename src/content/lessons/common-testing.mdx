## 测试策略与测试替身

Vitest 或 Jest 的 mock 思维可以迁移，但 Python 和 C++ 的依赖替换方式不同。更稳的设计是先用接口隔离外部世界，再选择 mock、fake 或真实集成测试。测试的目的不是把实现每一行重演，而是控制时间、网络、文件、随机数和设备这些不确定性，让失败可重复。跨语言迁移还要避免只测试“类型能编译”：协议和边界需要运行时样例。

### 从单元测试到集成测试

纯函数优先测试，外部依赖留在少数适配器。fake 适合模拟完整协议，例如一个内存文件仓库或固定响应的模型客户端；mock 适合验证调用边界，但不应让测试绑定太多内部调用次数。集成测试连接真实序列化、文件或 HTTP 组件，少量端到端测试验证入口组合。每一层都要覆盖失败、超时、空输入、重复调用和取消。

```python
class FixedClock:
    def __init__(self, now: float):
        self.now = now

def is_fresh(expires_at: float, clock: FixedClock) -> bool:
    return expires_at > clock.now

assert is_fresh(110, FixedClock(100))
assert not is_fresh(100, FixedClock(100))
```

### 替换时间、网络和文件

不要在核心函数内部直接调用系统时钟、读取全局环境或创建 HTTP 客户端。把 `Clock`、`FileStore`、`ModelClient` 作为接口/参数注入，生产环境传真实实现，测试传固定 fake。Python 可以用 fixture 和 monkeypatch，C++ 可以用抽象类或模板注入，JS/TS 可以传函数对象；三者都应确保替身行为符合真实协议，而不是返回过于理想化的数据。

### 常见错误与排错思路

常见错误是只断言 mock 被调用，却没有验证输出契约；另一个是测试使用当前时间和真实网络，偶发失败后重跑就通过。排错时记录测试输入、随机种子、fake 响应和耗时，先把外部依赖替换成确定值，再逐步恢复集成层。C++ 若测试难以链接，检查接口是否包含实现细节；Python 若 patch 不生效，确认被替换的是“使用它的模块”而不是原始定义模块。

## 栈、堆与对象生命周期

JS 和 Python 通过垃圾回收管理大部分对象，但引用和闭包仍可能让大对象存活更久。C++ 进一步要求你理解作用域、栈对象、堆对象和智能指针的所有权。迁移到 AI 或机器人程序时，图像、点云和张量的内存量很大，生命周期不清会表现为内存峰值、延迟抖动、悬空引用或 double free。先画出对象从创建到最后一次使用的时间线，再决定复制、借用还是共享所有权。

“在堆上”不等于“安全”：垃圾回收只保证仍可达对象不会被回收，不能阻止闭包持有过大的 buffer；`shared_ptr` 只保证引用计数，不会自动解决循环引用或数据竞争。真正重要的是谁拥有存储、回调何时执行、异步任务取消后谁负责释放。

### 作用域、闭包和借用

闭包捕获会延长或改变数据的生命周期。JS/TS 中回调捕获 `Uint8Array`，Python lambda 捕获列表，都会让对象在回调仍存活时继续占用内存；C++ 若按引用捕获局部变量，回调晚执行就会悬空，按值捕获又可能复制大缓冲区。可以只捕获必要的标量，或明确捕获 `shared_ptr`/移动所有权，但要评估引用计数和复制成本。

```cpp
auto make_reader(std::shared_ptr<const Buffer> buffer) {
  return [buffer = std::move(buffer)]() -> std::size_t {
    return buffer->size();
  };
}
```

### 栈、堆和资源释放

小的临时值适合栈对象，离开作用域自动销毁；大块或跨异步边界的数据需要稳定存储，并用 RAII、上下文管理器或 finally 释放文件、锁和设备句柄。Python 的引用计数实现细节不能替代显式关闭文件/网络连接，JS 的 GC 也不能及时释放原生 GPU 资源。对 C++，优先 `vector`、`unique_ptr` 和拥有明确析构的类型，少用裸 `new/delete`。

### 常见错误与排错思路

内存持续增长时，先查缓存、闭包、全局列表和未结束任务是否仍持有引用；C++ 崩溃时用 AddressSanitizer 查越界、use-after-free 和 double free。若异步回调读到旧数据，记录 buffer id、创建/释放时间和任务完成时间。不要一看到内存高就改成 `shared_ptr`：先确认所有权图，循环引用可能把问题变成永久泄漏。

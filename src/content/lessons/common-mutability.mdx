## 可变性、身份与副作用

JavaScript 对象通过引用共享，Python 也有可变 list 和 dict，C++ 则把值、引用和指针的区别暴露在类型里。数据是否被原地修改，会影响缓存、并发和测试。迁移时应先写出所有权：调用方是否仍持有旧值，函数是否借用对象，返回结果是否拥有独立存储。没有这个约定，语法看似正确，实际可能让模型特征、机器人状态或缓存被悄悄改写。

### 用不可变快照隔离阶段

如果事件要被多个消费者读取，优先创建新对象或冻结内部模型；如果确实要原地更新，限定在一个拥有者内部，并让函数名/文档说明副作用。C++ 的 `const Item&` 表示只读借用，按值参数表示复制或移动；Python 可以用 `dataclass(frozen=True)`，JS/TS 可以使用结构化复制或只读类型，但运行时仍要防止嵌套对象被改写。

```typescript
function withTag(item: Item, tag: string): Item {
  return { ...item, tags: [...item.tags, tag] };
}

const before = { id: "a1", tags: ["raw"] };
const after = withTag(before, "validated");
```

### 副作用如何影响工程

原地修改可能减少复制，适合明确拥有缓冲区的高频 C++ 算法；但跨线程共享同一可变对象会引入锁和竞态。Python/JS 的闭包若捕获可变列表，异步回调执行顺序会改变结果。AI 批处理可以在边界把输入转成只读批次，机器人控制状态则应区分“最新快照”和“待处理命令”，不要让消费者反向修改生产者数据。

### 常见错误与排错思路

最常见错误是浅拷贝：只复制外层对象，嵌套 `tags` 或 `metadata` 仍和原对象共享。排错时比较修改前后两个引用/地址，给嵌套字段打印身份，并写连续调用测试；C++ 若出现 double free 或悬空指针，检查裸指针是否表达借用还是所有权，优先改成 RAII 容器。若结果依赖测试顺序，先消除共享全局状态，再考虑加锁。

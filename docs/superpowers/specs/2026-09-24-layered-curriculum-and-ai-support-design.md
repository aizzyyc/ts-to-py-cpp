# 分层课程与 AI 辅助学习设计

## 1. 背景与目标

LangShift 的核心定位保持不变：帮助已经具备 JS/TS 项目经验的开发人员，系统掌握 Python 和 C++ 的基础知识、进阶知识，以及跨语言的行为和工程思维迁移。

当前仓库已经有 92 节课程、三条学习路线、代码对照、练习、答案、进度和阶段导航。本次不删除课程、不改成项目制课程，也不引入在线执行、账号同步或复杂 AI Tutor。目标是降低学习过程中的迷失和重复阅读，让开发人员能够：

- 知道哪些内容是当前阶段必须掌握的基础；
- 知道哪些内容属于进阶主题，可以按目标选择；
- 在每个知识阶段用小案例验证理解，而不是只读文章；
- 使用 AI 解释、出题、排错和复习，但仍由开发人员运行代码并确认结果。

## 2. 非目标

- 不把 92 节课压缩成纯项目教程；
- 不移除现有 Python / AI、C++ / Robotics 的进阶主题；
- 不为每节课创建大型独立项目；
- 不实现在线编译、在线判题、账号系统、跨设备同步或后端 AI 服务；
- 不声称示例代码已经在所有操作系统、编译器、Python 环境或真实机器人上运行。

## 3. 学习信息架构

课程内容保留现有三条 track 和阶段结构，在课程元数据和 UI 中增加轻量分层：

- `基础`：通用迁移基础、Python 基础、C++ 基础，是默认推荐顺序；
- `进阶`：数据、模型、并发、ROS 2、性能、部署等主题，按目标路线继续；
- `案例`：将多个概念组合成 20–40 分钟的小案例，用于验证和迁移；
- `查阅`：不改变课程内容，只在路线中标记为可以按需回看。

分层不改变课程总量。路线页默认突出当前目标路线和推荐顺序；全部课程仍可通过完整路线、搜索和阶段导航访问。

每节课的学习目标改为四级掌握标准：

1. 能解释：说清概念和 JS/TS 的行为差异；
2. 能阅读：能在现有代码中识别这种写法和边界；
3. 能修改：能独立完成变式练习并通过运行验证；
4. 能排错：能根据输出、日志、测试或编译错误定位问题。

## 4. 课程详情页调整

在现有课程详情页中保留“学习目标—代码对照—练习—结论—下一节”结构，增加三个轻量区块：

### 4.1 课程标签

在标题附近显示课程级别和学习类型，例如“基础 · 必学”或“进阶 · 案例”。标签只用于认知和筛选，不使用重型卡片或大面积颜色。

### 4.2 本节掌握标准

在学习目标后显示四条可检查陈述，默认对应课程内容；完成按钮旁提示“完成阅读”与“完成掌握检查”是不同动作。现阶段掌握检查仍为本地清单，不引入自动判题。

### 4.3 AI 学习卡

增加可复制的提示词卡片，覆盖四类动作：

- 概念迁移：解释 JS/TS 与 Python/C++ 的语义差异；
- 变式练习：生成同难度但不同输入的题目；
- 排错辅助：要求 AI 先分析真实错误输出，再提出最小修改；
- 复习检查：要求 AI 不直接给答案，先通过问题检查理解。

提示词必须提醒开发人员提供真实代码和输出、先运行再判断，并禁止把 AI 生成但未验证的结果当成事实。

## 5. 案例内容设计

案例是知识验证层，不替代基础和进阶正文。第一批案例沿用当前课程主线，避免引入新的领域：

- 通用：JSONL 事件契约与跨语言处理；
- Python：数据清洗 CLI、HTTP 输入校验、最小推理接口；
- C++：RAII 资源管理、有界消息队列、传感器消息处理。

每个案例包含：场景、前置知识、最小代码、预期结果、一个故障实验、一个变式练习和验收清单。案例代码优先放入独立的 `examples/` 目录，课程页面通过链接或复制入口引用；课程正文继续负责解释概念和迁移模型。

第一阶段只要求建立一个代表性跨语言案例和一个 Python / C++ 各自的小案例，不要求一次性为 92 节课程补齐独立代码仓库。

## 6. 练习层级

保留现有每节课的主练习、提示和答案，并在内容规则中鼓励三种题型按阶段出现：

- 预测题：先预测输出、类型、异常或构建阶段；
- 修复题：从一个最小错误开始定位和修复；
- 变式题：改变输入、边界或工程约束后重新实现。

不要求每节课都增加三个独立组件。可在同一 `Exercise` 中呈现一个主任务，并在提示或延伸部分给出预测和变式，控制页面长度。

## 7. 路线页调整

- 保留完整 92 节路线和阶段导航；
- 在路线顶部显示基础、进阶、案例的数量和建议顺序；
- 目标路线默认展示对应语言的基础与进阶阶段；
- 共同基础仍作为单独入口，不混入 AI / Robotics 专线课程列表；
- 显示 Python 路线和 C++ 路线的预计总学习时间；
- 默认不同时展开三条路线的首个阶段，减少首次进入时的信息压力；
- 继续保留进度、继续学习、阶段检查点和下一节导航。

## 8. 数据和实现边界

课程 frontmatter 增加最少的分层字段，建议为 `level` 与 `learningMode`，由内容 schema 校验。已有课程先按当前 track、order 和阶段规则填入默认值，再对案例课程显式标记，避免大规模重写正文。

新增可复用组件或数据模块：

- `LessonLevelBadge`：展示基础 / 进阶 / 案例标签；
- `AiStudyCard`：展示和复制 AI 学习提示；
- `lesson-levels.ts`：提供默认分层和统计函数；
- 案例元数据：关联前置课程、代码目录和验收说明。

## 9. 验收标准

- 92 节课程仍然可访问，现有路线筛选、搜索、进度和静态构建不回归；
- 每节课程可以看出基础 / 进阶和案例关系，但不增加大面积视觉噪声；
- 课程详情页能看到掌握标准和至少一组 AI 学习提示；
- 至少一个跨语言案例和一个 Python / C++ 小案例拥有独立代码、输入、预期输出和测试或验证说明；
- `npm test`、`npm run check`、`npm run build` 全部通过；
- 案例代码有独立的静态检查或构建门禁，不能只验证页面文本；
- 桌面和窄屏页面均能阅读标签、练习和 AI 学习卡；
- README 明确说明课程是基础与进阶知识学习工具，案例用于验证，AI 不能替代运行和测试。

## 10. 分阶段实施

### Phase 1：内容分层和学习卡

先增加元数据、路线统计、标签、掌握标准和 AI 学习卡，不新增大量课程正文。

### Phase 2：代表性案例

新增一个跨语言事件案例，以及 Python / C++ 各一个小案例；补充独立代码、固定输入和验证说明。

### Phase 3：练习和验收优化

为高频基础和进阶主题补充预测题、修复题、变式题和阶段复习；根据实际使用反馈再调整课程分层。

### Phase 4：验证和发布

运行课程测试、类型检查、生产构建、案例静态检查和浏览器验收，再决定是否发布到 GitHub Pages。

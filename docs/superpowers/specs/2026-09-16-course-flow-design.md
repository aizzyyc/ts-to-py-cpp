# LangShift 课程流程升级设计

## 目标

在不重写现有 92 节课程、不引入后端和账号系统的前提下，把 LangShift 从“课程目录 + 详情页”升级为一条可继续、可检查、可完成的学习流程。学习者打开 `/learn` 后应能立刻知道当前路线、当前阶段、下一节课和完成进度；学习完一节后应能明确地进入下一节或阶段检查。

## 设计原则

- 保留现有 Astro + MDX + 静态 Pagefind 架构。
- 课程内容继续作为主要资产，流程增强通过元数据、页面组件和浏览器端 localStorage 实现。
- 不伪造在线编译或自动判题结果；阶段检查以自测清单和可验证任务呈现。
- 兼容现有 `langshift-progress:v1` 数据，旧用户的完成记录不可丢失。
- AI 路线只使用 Python，机器人路线只使用 C++，全部路线仍可查看通用迁移基础。
- 所有新增流程在移动端保持单列、键盘可操作和清晰的视觉顺序。

## 学习流程

学习入口依次包含：

1. 选择 AI 或机器人目标，或查看全部路线。
2. 继续学习卡片显示当前目标、当前阶段、下一节未完成课程和阶段进度。
3. 路线页按阶段分组课程；每个阶段展示课程数、预计时间、完成数和阶段检查点。
4. 课程详情页保持现有“迁移解释、代码对照、练习、答案、资源”结构，底部形成“完成本节 → 下一节”的闭环，并显示当前阶段。
5. 每条路线最后以结课项目结束，项目卡片说明预期产出和完成标准。

## 阶段模型

新增 `src/lib/course-flow.ts`，以 track 和课程 order 提供确定性阶段定义，不修改现有 lesson slug、order 或 frontmatter。

- 通用迁移基础：运行与语法、工程边界、并发与可靠性、综合项目。
- Python：Python 基础、工程与数据输入、数据与模型、服务化与结课项目。
- C++：C++ 基础、系统工程、ROS 2 工程、诊断与结课项目。

每个阶段包含 `id`、`track`、`title`、`description`、`startOrder`、`endOrder`，可选 `checkpointLessonId` 和 `project`。阶段课程由 order 范围计算，若范围没有课程则不渲染。

## 进度模型

保留 `ProgressState.version = 1` 和原有 `completedLessonIds`、`lastLessonId` 字段，增加可选兼容字段 `lastViewedLessonId`。打开课程列表或课程详情的链接时记录最后查看课程；完成课程时继续更新 `lastLessonId`。旧的 localStorage JSON 没有该字段时按 `null` 处理。

下一节计算优先使用当前目标路线；在该路线中按 order 找到第一个未完成课程。若当前正在查看一节未完成课程，则继续卡片优先指向它；否则指向第一个未完成课程；全部完成时指向结课项目或显示“路线已完成”。

## 页面变化

### `/learn`

- 保留当前顶部标题和总进度。
- 新增继续学习卡片，显示“继续学习”“当前阶段”“下一节课程”和行动按钮。
- 课程列表改为阶段标题，每个阶段显示描述、完成数、预计时间和检查点提示。
- 结课项目阶段使用明确的 project 样式，但仍然复用现有课程详情页。

### 课程详情页

- 在课程眉标题中增加当前阶段信息。
- 在底部导航上方增加阶段进度条和检查点提示。
- 课程链接点击时记录 `lastViewedLessonId`，完成按钮行为保持可重复点击取消完成。

## 验收标准

- 新用户打开 `/learn` 能看到路线和第一节推荐；已有进度能看到正确的继续学习课程。
- AI / 机器人筛选只影响对应路线，阶段统计与页面进度保持一致。
- 三条 track 的每一节课程都恰好属于一个阶段，阶段顺序和课程 order 一致。
- 旧版进度 JSON 仍能解析，新增字段不会破坏已有完成记录。
- `npm test`、`npm run check`、`npm run build` 全部通过。
- 浏览器验证桌面和当前移动视口：继续卡片、阶段统计、课程完成、下一节导航和课程搜索均可用。

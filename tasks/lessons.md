# 课程开发经验记录

- 用户进一步明确：不必机械限制每条路线为 30 节，应根据内容密度适当增减。
- 当前课程数量方案是迁移基础 26 节、Python / AI 30 节、C++ / Robotics 36 节，总计 92 节。
- 课程数量验收必须按 track 分别统计，同时检查课程顺序和前置依赖，不能只检查总数。
- 扩展课程时必须保持每节课的完整结构：JS/TS 出发点、目标语言对照、关键概念、练习、提示或答案、总结和前后导航。
- 课程选题应优先参考官方资料，并将 AI 路线连接到 NumPy / PyTorch，将机器人路线连接到 CMake / ROS 2，而不是只增加语言语法课。
- 用户进一步明确：选择 AI 或机器人路径后，页面只能展示当前路径的课程；每条路径都要包含对应语言自己的迁移基础，不能依赖一套混合的共用基础替代。
- 路径隔离验收应检查 AI 只包含 Python、机器人只包含 C++，同时验证 Python/C++ 路线前段确实覆盖 JS/TS 到目标语言的基础迁移。
- 用户指出每节课页面内容仍然过少；课程结构组件齐全不等于讲解详细，后续验收必须同时检查正文深度、示例数量、练习完整度和预计学习时长的匹配度。
- 扩写课程时，正文深度验收采用每节至少 900 个非空白正文字符、4 个教学标题和 2 个代码示例；仅有 frontmatter 或组件不应被视为课程完成。
- 用户再次指出：即使达到字符数标准，课程仍可能只有知识点罗列，不能支撑从零学好 Python；后续必须以“概念解释 + 递进例子 + 运行结果/思考 + 常见错误 + 练习 + AI 场景迁移”验收，而不是以字数作为唯一完成条件。
- 本轮 Python 深度重写后，课程验收保留语义门槛和资源链接检查；字符数只能作为下限，不是课程质量结论。
- 用户指出：Python 已按教材级深度重写，但 C++ 仍停留在上一轮结构扩写，不能把两条路线的完成标准混为一谈；后续 C++ 也必须达到同等的概念、例子、验证、排错和行业场景标准。
- 课程流程验收不能只看课程数量和正文深度；还要检查目标选择、继续学习、阶段进度、检查点、完成后的下一节推荐，以及路线完成后的结课项目入口。
- 用户反馈 GitHub Pages 显示 `ERR_CONNECTION_CLOSED`；排查确认 Pages 服务端返回 200、DNS 正常、GitHub 远程正常，故障发生在旧的内置浏览器连接。遇到站点无法访问时，应先区分发布状态与客户端网络或标签状态，不要在没有服务端证据时修改站点配置或本机代理。
- 用户反馈学习路线总览左侧与主目录重复列出课程，且阶段导航缺少可见选中态；总览应采用阶段锚点导航并随滚动同步高亮，课程详情页保留逐课导航。
- 用户再次反馈导航点击后仍看不到当前项；排查发现线上生成的 `<a>` 保留了字面量 `class:list-active="true"`，高亮类没有真正输出。今后导航回归必须检查生成 HTML 中的 class/aria-current，并在真实页面确认选中态，而不只检查源码或样式规则。
- 用户认为主导航浅蓝色整块圆角选中态太丑、视觉太重；后续选中态应醒目但克制，优先考虑品牌色文字与细线/标记，避免整块填充和描边，并保留清晰的 hover 与无障碍当前状态。
- 用户指出课程页上一节/下一节导航中箭头与标题分离、两组内容挤在中间；链接布局要让方向箭头紧邻对应标题组，并明确左右对齐，不能用 `space-between` 把关联内容拉开。
- 用户补充顶部“学习路线 ↔ 搜索课程”切换后页面会偏移；验收客户端导航时要同时检查不同页面主内容起始基线、侧栏连续切课及浏览器前进/后退。进度相关的交互验证应使用隔离存储环境，避免污染用户本地进度。
- 用户指出前一轮顶部切换仍抖动；启用 ClientRouter 不代表动画消失，Astro 默认 fade 也必须纳入根因检查。用户报告视觉问题后，应在实际预览中复核而非只凭路由和布局检查推断已修好。
- 用户进一步纠正：所指位置是顶部导航栏的导航文字本身左右移动，并非页面偏移或整页动画；排查导航抖动时要区分文字宽度变化、页面滚动和切页过渡，核对 active 样式是否改变字重等布局属性。
- 用户再次反馈路线与搜索往返时仍能看到偏移；上一轮只量了导航文字的水平宽度，没有确认 Astro 页面替换和 active 状态完全完成，也没有比较纵向位置和视口/滚动条。复测必须在目标页内容和当前态实际更新后比较完整布局。
